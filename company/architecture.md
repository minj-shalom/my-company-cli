# 회사 운영 구조

> 이 AI 회사가 어떻게 일하는지의 구조다. 만드는 제품의 설계는 프로젝트 레포의 `docs/architecture.md`에 있다.

## 구성 요소
| 요소 | 위치 | 역할 |
|---|---|---|
| COO (메인 세션) | `CLAUDE.md` | CEO와 대화하고 부서에 업무를 배정, 결과 보고 |
| 직원 | `.claude/agents/` | 서브에이전트 1개 = 직원 1명 (프리셋이 전문 직원을 추가) |
| 조직도 | `company/org.md` | 부서, 보고 라인의 원본 |
| 규칙 | `.claude/rules/` | git 워크플로, 코드 스타일, 보안 규칙 |
| 반복 실행 | `.claude/loop.md` | 티켓을 이어서/새로 가져와 처리하는 절차 |
| 업무 상태 | `company/tickets/`, `decisions/`, `reports/` | 티켓, 결정 카드, 보고서 (마크다운이 원본) |
| 재무 | `company/finance/` | 예산 정책, 사용량 기록 |
| 설정과 권한 | `.claude/settings.json`, `company/project.md` | 허용·차단 명령, 프로젝트 이름과 경로 |

## 업무 흐름
CEO가 비전·미션·지시를 주면 COO가 pm·CTO와 목표를 티켓으로 풀고, 승인된 티켓을 담당 직원에게 배정한다.
구현 후 reviewer-qa가 검수하고, 결과는 보고서로 남긴다. 사람 판단이 필요하면 결정 카드를 남기고 다른 티켓으로 넘어간다.

## 위임 구조
- 조직도는 계층이지만 실행은 평평하다. 서브에이전트는 다른 서브에이전트를 호출할 수 없으므로 배정은 COO만 한다.
- CTO·CFO는 계획과 점검 결과를 반환하고, COO가 그에 따라 움직인다.

## 레포 구조
- 이 레포(`my-company-cli`)와 프로젝트 레포(`project_dir`)는 각각 독립 git 레포다.
- 제품 문서(미션, 아키텍처)는 프로젝트 레포의 `docs/`에 둔다. 이 레포에는 회사 운영 문서만 둔다.
- 브랜치와 커밋 규칙은 `.claude/rules/git-workflow.md`를 따른다.

## 안전장치
- 푸시와 PR 머지는 사람 컨펌 후에만 한다 (`ask` 권한). `master`/`develop` 직접 푸시, 강제 푸시는 차단한다.
- `.env*`, `~/.ssh`, `~/.claude` 읽기와 `rm -rf`, `sudo`는 차단한다.
- 사용자 토큰과 인증 파일을 읽고 저장하는 코드는 쓰지 않는다.

# 웹 보안 규칙

웹 프론트엔드/백엔드 코드를 건드리는 모든 작업에 적용한다. reviewer-qa는 이 문서로 검수한다.

## 입력과 출력
- 모든 외부 입력(요청 본문, 쿼리, 헤더, 파일 업로드)은 서버에서 스키마로 검증한다. 클라이언트 검증은 편의일 뿐이다.
- DB 접근은 파라미터 바인딩/ORM만 쓴다. 문자열로 SQL을 조합하지 않는다.
- HTML 직접 삽입(`innerHTML`, `dangerouslySetInnerHTML`) 금지. 불가피하면 sanitize한다.
- 파일 업로드는 타입, 크기, 저장 경로를 제한하고 원본 파일명을 그대로 경로에 쓰지 않는다.

## 인증과 권한
- 비밀번호는 검증된 해시 알고리즘(argon2, bcrypt 등)으로 저장한다. 직접 만든 암호화를 쓰지 않는다.
- 모든 보호된 엔드포인트에서 인증과 **권한(소유자 확인)** 을 서버에서 검사한다.
- 세션/토큰 쿠키는 `HttpOnly`, `Secure`, `SameSite`를 설정한다. 상태 변경 요청은 CSRF를 방어한다.
- 토큰을 URL이나 로그에 남기지 않는다.

## 설정과 비밀
- 시크릿은 환경변수나 시크릿 매니저로 주입한다. 코드와 저장소에 넣지 않는다. `.env*`는 커밋하지 않는다.
- CORS는 허용 출처를 명시한다 (`*` 금지, 자격 증명 사용 시 특히).
- 보안 헤더(CSP, `X-Content-Type-Options` 등)와 HTTPS를 전제로 설정한다.

## 운영
- 에러 응답에 스택 트레이스, 내부 경로, SQL을 노출하지 않는다.
- 로그에 비밀번호, 토큰, 개인정보를 남기지 않는다.
- 의존성은 최소로 하고, 추가 시 유지보수 상태와 알려진 취약점을 확인한다.
- 로그인, 비밀번호 재설정 등 민감한 엔드포인트에는 요청 제한(rate limit)을 둔다.

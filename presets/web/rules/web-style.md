# 웹 코드 스타일

> 공통 `code-style.md`에 더해 적용한다. 린터/포매터를 도입하면 그 설정을 우선한다.

## 공통
- TypeScript를 쓰는 경우 `strict: true`, `any` 금지 (불가피하면 `unknown` + 좁히기).
- API 요청/응답 타입은 프론트와 백엔드가 공유할 수 있는 한 곳에 정의한다.
- `async/await`를 쓰고, 에러는 삼키지 말고 처리하거나 위로 전달한다.
- 파일은 한 가지 책임. 길어지면 분리한다.

## 프론트엔드
- 컴포넌트는 작게, 상태는 필요한 곳에 가깝게 둔다. 서버 상태와 UI 상태를 구분한다.
- 로딩/빈/에러 상태를 항상 처리한다.
- 접근성: 시맨틱 태그, 폼 레이블, 키보드 포커스, 이미지 대체 텍스트.

## 백엔드
- 계층을 나눈다 (라우트/핸들러 → 서비스 → 데이터 접근). 핸들러에 비즈니스 로직을 넣지 않는다.
- API는 일관된 에러 형식과 적절한 상태 코드를 쓴다.
- 마이그레이션은 되돌릴 수 있게 작성하고, 운영 데이터를 고려한다.

## 테스트
- 새 기능과 버그 수정에는 테스트를 함께 둔다. 외부 서비스는 mock으로 대체한다.
